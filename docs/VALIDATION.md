# Luma Piano 0.1.4 검증 기록

검증일: 2026-10-24 (Asia/Seoul)

## 0.1.4: Kontakt 재시작 후 녹음 대상 갱신

- Kontakt 7의 프로세스가 19592에서 26332로 바뀌었지만 열린 스튜디오의 선택값은 19592로 남아, 녹음 시작에 실패한 것을 확인했습니다.
- 녹음 버튼은 최신 소스 목록을 먼저 읽습니다. 유효한 선택은 유지하고, 종료된 선택 대신 Kontakt가 하나만 실행 중이면 자동 갱신합니다. 여러 인스턴스는 명시적인 선택을 요구합니다. 조회 오류나 빈 목록에서는 오래된 PID를 보내지 않으며 중복 클릭도 막습니다.
- 서버도 녹음 직전 선택한 PID가 현재 Kontakt 목록에 있는지 확인합니다. 확인 도중 종료된 경우 한국어 안내와 목록 갱신 신호를 보내고, 네이티브 도우미도 활성화 직전 프로세스 이름을 확인합니다. 목록 조회는 5초 제한과 종료 시 취소를 지원합니다.
- 단위·통합 테스트 70개, 새 UI 시나리오 8개 및 기존 UI·재생 검증을 통과했습니다. 현재 Kontakt 26332를 대상으로 별도 임시 파일에 약 1초 실제 녹음도 성공했습니다: 44.1 kHz stereo, peak 0.1000, discontinuities 0. 검증 파일은 테스트 종료 후 정리했고 사용자 원본은 바꾸지 않았습니다.

## 0.1.3: 주기적 틱과 실제 영상 프레임 손실

- 최신 실제 녹음 `a58010cf-1718-4d8b-acb5-7aea54d8e852`(81.9225초)을 검사했습니다. 무음 삽입과 클리핑은 없었지만 원본 WAV에 약 7.18초 간격의 급격한 파형 단절이 남았습니다. 이전의 무음·peak 검사는 이 오류를 잡지 못했습니다.
- 사용자 설정은 Kontakt WASAPI Shared / AudioBox 22 VSL / 44,100 Hz / 309 samples입니다. 패킷 시각 간격은 309 ÷ 44,100 = 7.00680272 ms인데 48 kHz 캡처는 매번 336 frames를 반환해 정수 프레임 변환 오차가 누적됐습니다.
- 같은 실제 연주를 20초간 동시에 비교 녹음했습니다. 44.1 kHz PCM16은 309 frames/packet, 시계 오차 0, 내부 클릭 후보 0이었습니다. 48 kHz PCM16과 float32는 모두 336 frames/packet, 약 19.4 ms 시계 오차와 7.2 / 14.4초의 급격한 파형 단절을 보였습니다. 리미터나 샘플 비트 깊이로 해결되는 현상이 아니었습니다.
- 녹음기에 44.1 / 48 kHz 선택을 추가하고 현재 장비에 맞는 기본값 44.1 kHz를 적용했습니다. 기존 48 kHz 파일은 계속 지원하고 원본은 수정하지 않았습니다. 증거: `.runtime/audio-ab-waveforms.json`, `.runtime/audio-ab-1792821004461-*.wav`.
- 기존 영상은 실제 비디오 771 frames / 약 81.73초 = 9.42 fps였습니다. 파일을 60fps로 변환하는 것만으로는 잃어버린 움직임이 복원되지 않았습니다.
- 새 영상 경로는 각 frame index ÷ 60의 화면을 WebCodecs H.264로 모두 인코딩하고, 원본 WAV를 MP4에 합칩니다. 벽시계나 화면의 requestAnimationFrame 속도에 맞춰 프레임을 건너뛰지 않습니다. 인코더 대기열과 업로드 버퍼는 제한하고, FFprobe의 실제 decoded frame 수가 기대값과 다르면 저장을 실패 처리합니다.
- 2.4초 합성 영상은 144 frames 생성·디코딩과 모든 PTS를 검증했습니다. 움직이는 1초 구간 60 frames의 연속 중복은 0이었습니다. 143/144 frames 입력은 거부·정리됐고, 취소·음원 없는 영상·앱 종료 정리도 통과했습니다.
- 사용자 81.9225초 연주도 현재 디자인으로 다시 출력했습니다. 약 165초에 4,916 frames가 생성됐고, 실제 MP4 디코딩에서도 4,916 frames와 모든 PTS = index ÷ 60을 확인했습니다. 10–11초의 60 frames에 연속 중복이 없었습니다. 결과는 `recordings/a58010cf-1718-4d8b-acb5-7aea54d8e852-60fps-fixed-20261024T055750448Z.mp4`이며, 원본 WAV의 틱을 후처리로 제거한 파일은 아닙니다.
- 최신 녹음 전체를 격리 브라우저에서 재생했을 때 중간 탐색·버퍼링 오류는 없었습니다. 재생 시작 지연으로 화면보다 약 130 ms 늦고 마지막 꼬리가 잘릴 수 있는 별도 문제를 발견해, 오디오가 있는 화면은 실제 미디어 시각을 기준으로 그리도록 수정했습니다.
- 최종 자동 검사: `npm test` 66개, 네이티브 자체검사 10그룹, UI·재생 시작 지연·끝부분 보존·샘플레이트 선택·오프라인 영상 검증 통과. 늦은 오디오 준비 테스트는 OS 타이머 속도에 의존하지 않도록 수동 준비 신호와 명시적 QPC 시각으로 검증합니다.

## 0.1.2 후속 수정

- 라이브 서버에 key-up 없이 남아 있던 9개 음표를 확인했습니다. 동일 피아노 건반 재타건 시 이전 물리 누름 상태를 정리하도록 보강했습니다. 녹화·재접속 경계의 note-off 중복과 초기화 이전에 발생한 지연 입력 재유입도 방지했습니다. 최초 누락 원인은 과거 입력 기록이 없어 확정하지 않았습니다.
- 수정본 적용 후 사용자가 페달을 밟은 채 오버레이를 닫고 페달을 뗐을 때 노트가 정상 종료된다고 확인했습니다. 실제 서버에서도 heldKeys 0, soundingVoices 0을 확인했습니다.
- 삭제 확인·취소·재생 중 삭제·다른 연주와 영상 보존을 격리된 테스트 데이터로 검증했습니다. 삭제 파일은 `recordings/.trash/`에 보관하며, 사용자 연주 파일은 테스트에서 삭제하지 않았습니다.
- 삭제 버튼이 있는 목록과 확인창을 1920 / 1280 / 390 화면에서 검사했습니다. 가로 넘침과 브라우저 오류가 없고 HTML 형식의 제목도 텍스트로만 표시됩니다.
- 기존 27.638초 녹음은 peak −12.54 dBFS, clipped sample 0이지만 약 5.17초마다 241-frame 무음이 반복됐습니다. 시스템 시각에 맞춰 PCM을 삽입하던 캡처 로직과 일치했습니다.
- 수정한 도우미로 별도 20.002초 실제 Kontakt 녹음을 검사했습니다. peak −15.16 dBFS, clipped sample 0, 내부 연속 무음 구간 0, 캡처 discontinuity 0을 확인했습니다. `.runtime/capture-fixed-1792819779574.wav`와 진단 JSON에 보관했습니다. 기존 WAV는 변경하지 않았습니다.
- 최종 도우미의 별도 6.001초 실제 캡처도 내부 연속 무음·클리핑·discontinuity 0이었습니다. 이 장치의 패킷은 336 frames / 7.0068 ms이고 장치 위치는 항상 0임을 확인했습니다. 사용할 수 없는 위치를 reset으로 처리하지 않고 PCM을 연속 저장하며, 13개 시계 기준점을 사용해 MIDI 시각을 실제 PCM 위치에 맞췄습니다. 원래 시각은 `wallTime`으로 보존합니다. 6시간 길이의 합성 시계 오차 테스트도 통과했습니다.
- 최종 `npm test` 64개, 네이티브 self-test 9개, 화면·재생 설정·영상 내보내기 검증을 통과했습니다. 설정 변경 시 불필요한 오디오 탐색은 0회, 명시적 50 ms 탐색은 1회로 확인했습니다. 삭제와 다운로드의 경합·중단·읽기 오류 후에도 서버와 파일 잠금이 정상 동작했습니다.

## OBS용 소스와 데스크톱 오버레이

- `/stage?transparent=1`에서 UI 없이 1920×1080 전체 화면, 투명 배경 alpha 0, 건반 alpha 255를 확인했습니다.
- 데스크톱 창은 전체 모니터 크기·항상 위·비활성 창으로 열리고, 실제 Windows HWND의 `WS_EX_TRANSPARENT`, `WS_EX_LAYERED`, `WS_EX_NOACTIVATE` 설정을 확인했습니다.
- 사용자 피드백으로 확인된 클릭 통과 문제는 마우스 전달 옵션을 제거하고 표시·로드 이후 설정을 재적용하는 방식으로 수정했습니다. 사용자가 수정 후 건반 영역에서도 클릭이 정상적으로 통과한다고 확인했습니다.
- 오버레이 전용 노트·건반 불투명도 슬라이더와 건반 숨기기를 제공합니다. 기본값은 노트 60%, 건반 18%입니다.
- 건반 단독 영역의 alpha가 기본 46에서 8% 설정 시 20으로 변하고, OBS 건반 alpha는 255로 유지되는 것을 검증했습니다. 노트 빛이 겹치는 영역은 별도 노트 레이어와 합성됩니다.

## 자동 검증

- `npm test`: 42개 통과. MIDI note/pedal/retrigger, 시간 정렬, 중도 녹음, 긴 서스테인 재접속, panic, MIDI 파일, 오디오 도우미 오류·종료·저장 경합, 설정 저장, 출처 제한, 투명도 합성을 포함합니다.
- `npm run test:ui`: 1920 / 1280 / 390 화면, 방향·테마·투명 소스·불투명도 변경 검증. 가로 넘침과 브라우저 오류 없음.
- `npm run test:desktop`: 실제 Electron 오버레이 생성·닫기, 픽셀 투명도와 Windows 창 스타일 검증.
- `npm run test:export`: 1080p60 영상, 원음 동기화, MIDI-only 출력, 분할 업로드 순서·용량 제한, 취소·종료 시 임시 파일 정리 검증.
- 네이티브 MIDI 프로토콜 smoke test 및 WAV 형식 self-test 통과.

검증은 현재 개발 컴퓨터와 짧은 실제 연주를 기준으로 했습니다. 다른 오디오 드라이버나 컴퓨터에서는 녹음 미터로 실제 Kontakt 신호를 확인해야 합니다. 프로그램은 ASIO 등으로 캡처가 불가능할 때 시스템 전체 오디오로 임의 전환하지 않습니다.
