# EClone Piano 검증 기록

[README](../README.md) · [검사 실행 방법](DEVELOPMENT.md)

기준 버전: **0.1.5** · 2026-10-24

최종 로컬 검사: 단위·서버 77개, 네이티브 자체검사 11개 그룹, 전체 UI 검사, 다중 창 재생 11개 시나리오, 데스크톱 오버레이, 1080p60 영상 내보내기 모두 통과했습니다. 합성 2.4초 영상은 144프레임으로 디코딩됐고, 움직이는 1초 구간의 연속 중복 프레임은 0개였습니다.

## 2026-11-07: 폴더·공통 도구 정리

- 네이티브 코드를 `native/midi/`, `native/audio/`로 모으고 자동 검사와 수동 진단·문서 이미지 도구를 구분했습니다. 녹음 저장 경로와 파일 형식은 유지합니다.
- 프로젝트 경로, 검사 브라우저 선택, 합성 PCM WAV 생성 코드를 공통 모듈로 합쳤습니다. 단위·서버 77개, 네이티브 빌드·자체검사, MIDI 브리지 smoke, UI·다중 창 재생·오디오 소스, 1080p60 내보내기와 문서 이미지 생성을 새 경로에서 확인했습니다.
- 다중 창 검사의 백그라운드 페이지에 브라우저 타이머 절전을 끄는 옵션을 적용했습니다. 앱의 재연결 처리를 바꾸지 않고, 절전 지연 때문에 6초 대기 조건이 실패하는 것을 분리합니다. 실패 시 재생·소유권 상태도 보고서에 남깁니다.
- 과거 로컬 진단 자료를 SHA-256 목록과 함께 `.runtime/archive/`에 보관합니다. 새 산출물은 reports / screenshots / tmp로 나눕니다.

## 검증 범위

이 앱은 Windows 10 build 19045 / x64, Kontakt 7 standalone, USB MIDI 건반, loopMIDI, WASAPI Shared 출력에서 실제 연주·페달·프로세스 녹음을 확인했습니다. 다른 드라이버와 운영체제의 실제 오디오 경로까지 보증하는 것은 아닙니다. 새 환경에서는 짧은 첫 녹음의 미터와 WAV를 확인하세요.

테스트는 합성 MIDI·오디오 또는 가짜 네이티브 프로세스를 사용합니다. UI·영상 검사는 별도 서버와 임시 디렉터리를 사용하고 운영 녹음은 수정하지 않습니다. 공개 스크린샷도 합성 데모이며 실제 연주 파일은 저장소에 포함하지 않습니다.

## 0.1.5: 일반 사용과 공개 준비

- 제품명을 EClone Piano, 제작 브랜드를 EClone Games로 통일했습니다. 기존 가상 포트 이름과 `recordings/` 데이터를 계속 사용할 수 있습니다.
- `npm run doctor`로 필요한 구성요소와 기능별 준비 상태를 확인합니다. 설치·장치 연결·소리 캡처를 실행하지 않는 진단입니다.

- Play로 출력 창 전환, 다른 창의 일시정지, 무음 OBS, 오디오 OBS, 비소유 창 종료, 소유 창 연결 단절·재연결·종료를 격리 검증했습니다.
- 최초 설치·가상 MIDI 연결·OBS·녹음·내보내기·백업 문서를 추가하고 실제 앱 데모 스크린샷을 보관했습니다.

## 앞선 수정에서 확인한 사항

### 녹음 대상의 재시작

Kontakt를 재실행하면 프로세스 ID가 바뀝니다. 클라이언트는 녹음 직전 목록을 새로 읽고, 서버·네이티브 도우미도 실제 Kontakt 프로세스인지 다시 검사합니다. 단일 새 인스턴스는 자동 선택하고 여러 인스턴스는 명시적 선택을 요구합니다. 프로세스 종료·조회 실패·중복 클릭·시작 중 앱 종료를 테스트합니다.

### 연속 오디오와 샘플레이트

초기 구현의 시스템 시계 보정으로 PCM 중간에 반복적인 짧은 무음이 삽입되던 문제를 수정했습니다. 사용 가능한 장치 프레임 위치를 우선하고, 장치가 위치를 제공하지 않으면 받은 PCM을 연속 저장합니다. MIDI는 제한된 시계 기준점을 사용해 오디오 시간에 정렬하며 원래 이벤트 시각을 보존합니다.

특정 44.1kHz / 309-frame 출력 장치에서 48kHz로 캡처하면 약 7.2초마다 파형 단절이 발생했습니다. 동시 비교 녹음에서 소스와 같은 44.1kHz를 사용하면 사라졌습니다. 따라서 44.1/48kHz 선택을 제공하고 소스와 일치시키도록 안내합니다. 이후 실제 녹음에서도 기존 검출 조건의 주기적 클릭, 클리핑, 내부 무음 틈이 없음을 확인했습니다. 이는 모든 장치의 음질을 보장하거나 이미 저장된 잡음을 복구한다는 의미는 아닙니다.

### 실제 60fps 영상

이전의 실시간 화면 녹화는 렌더링이 밀릴 때 동작 프레임이 빠졌습니다. 현재 경로는 각 `frameIndex / 60` 시점을 순차 인코딩하고 FFprobe로 최종 프레임 수를 검증합니다. 2.4초 합성 영상의 144프레임과 실제 시각을 검사했고, 움직이는 1초 구간에 연속 복제 프레임이 없음을 확인했습니다. 143/144프레임처럼 일부가 빠진 입력은 저장 실패로 처리합니다.

오디오가 있는 스튜디오·OBS 화면은 실제 미디어 시각으로 그리며, 서버 재생 종료가 먼저 도착하더라도 WAV 끝부분을 보존합니다. 디자인 변경이 불필요한 오디오 탐색을 유발하지 않는지 별도로 검사합니다.

### 라이브 서스테인과 오버레이

같은 건반 재타건, 페달 해제, 녹음·재접속 경계의 중복 해제, 초기화 전에 발생한 지연 입력을 검사합니다. 정상적인 긴 누름과 페달 잔향을 시간 제한으로 강제 종료하지 않습니다. 실제 사용자가 페달을 밟은 상태에서 오버레이를 닫았다가 페달을 떼었을 때 노트가 끝나는 것을 확인했습니다.

건반까지 클릭이 통과하는 Windows 창 설정과 노트·건반의 개별 알파값을 확인했습니다. 사용자가 물리적 클릭 통과도 확인했습니다. 오버레이의 불투명도 변경은 OBS 화면에 영향을 주지 않습니다.

### 삭제와 원본 보존

삭제 취소, 재생 중 삭제, 다른 연주와 기존 영상 보존, HTML 형태 이름의 텍스트 표시를 검사합니다. 녹음·읽기·내보내기 중 파일은 삭제하지 못하며, 파일 이동 실패 시 복구하고 삭제 원본을 앱 휴지통에 남깁니다.
